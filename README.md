# КРиТ: бот MAX и программа управления

Проект состоит из двух самостоятельных программ.

- `bot` работает на сервере, принимает события MAX, проверяет доступ, хранит данные в отдельной PostgreSQL-базе и предоставляет защищённый API управления.
- `management` — настольная программа администратора клуба. Она запускается через PyCharm на компьютере администратора и подключается только к серверному HTTPS API. На сервер эта программа не устанавливается и прямого доступа к PostgreSQL не имеет.

Сейчас реализован экспериментальный этап: бот отвечает эхом только активным пользователям из базы. Остальным он предлагает пройти одноразовую авторизацию по подтверждённому номеру MAX.

## Возможности

- категории: ученик, родитель, учитель; роли хранятся отдельно от карточки человека и допускают дальнейшее расширение;
- двусторонние связи ученик ↔ родитель без дублирования карточек;
- ФИО, телефон, MAX user ID и включение/отключение доступа;
- маска номера `+7 (___) ___-__-__` в карточке клиента;
- одноразовая авторизация через подтверждённый контакт MAX;
- автоматическая привязка MAX ID к карточке по телефону и статус авторизации;
- автоматическое обновление данных в программе управления;
- архив клиентов с восстановлением и окончательным удалением;
- список непризнанных обращений;
- защищённое автоматическое подключение программы управления;
- защита от повторной обработки сообщения;
- Long Polling для эксперимента и Webhook для production;
- PostgreSQL для одновременной работы нескольких администраторов;
- вход в программу управления по логину и паролю;
- система обновлений в стиле HanziLab: GitHub Releases, SHA-256, безопасная распаковка и откат;
- основа для групп, занятий и уведомлений за 24 часа, 5 часов и 1 час.

Навигация программы разделена по рабочим областям. Режимы «Все», «Ученики», «Родители», «Учителя», «Запросы авторизации» и «Архив» находятся внутри раздела «Клиенты»; учебный процесс и рассылки вынесены в самостоятельные модули.

При первом обращении бот показывает кнопку передачи контакта. Бот проверяет HMAC-подпись MAX, ищет активную карточку с таким телефоном и один раз записывает MAX ID. Обычный текст с номером не принимается как доказательство владения.

## Запуск программы управления в PyCharm

```powershell
py -3.13 -m venv management\.venv
.\management\.venv\Scripts\python.exe -m pip install -e ".\management"
```

В PyCharm выберите `management/.venv/Scripts/python.exe`, откройте только `management/main.py` и нажмите **Run**. Бот на этом компьютере не запускается: он работает на сервере. Адрес HTTPS API уже задан в программе. Для эксперимента: логин `admin`, пароль `admin`.

Пункт **Проверить обновления** работает и в PyCharm, и в Windows-сборке. Готовые версии публикуются в GitHub Releases.

Windows-сборка создаётся одной командой:

```powershell
.\management\build_windows.ps1
```

Сценарий использует Python 3.13, очищает пути поиска DLL, проверяет реальное окно входа и запрещает сборку, если PyInstaller подхватил посторонние DLL.

Фирменные PNG, Windows ICO и аватар бота находятся в `management/src/krit_management/assets`. Программа уже использует `app_icon.ico` для окон, панели задач и будущего Windows-ярлыка.

## Сервер

На сервер устанавливается только содержимое `bot`. Сервис работает от отдельного системного пользователя, API слушает `127.0.0.1:8080`, а Nginx публикует выделенный HTTPS-маршрут. База `krit_bot` и роль PostgreSQL отдельные — существующие сайты и базы не используются.
