# Правила разработки проекта

## Общие принципы
- Перед изменениями изучай связанные участки кода и существующие соглашения проекта.
- Проверяй фактически установленные версии зависимостей; при необходимости обращайся к официальной документации.
- Сохраняй существующее работающее поведение и совместимость, если задача не требует иного.
- Изменяй только то, что относится к поставленной задаче. Не выполняй несогласованный рефакторинг.

## Экономия контекста и работа с инструментами
- Сначала определяй файлы, функции и классы, относящиеся к задаче; используй точечный поиск.
- Не загружай весь репозиторий, большие файлы и полные журналы без необходимости.
- Не перечитывай неизменённые файлы и не дублируй уже полученные результаты инструментов без причины.
- Для навигации по Python-коду предпочитай Serena, если сервер доступен и подходит для задачи.
- Используй Context7, когда требуется проверить актуальную документацию библиотеки или API.
- Для локального репозитория используй локальные инструменты Git, а GitHub MCP — для удалённых операций (PR, Issues и др.).
- Для проверки веб-интерфейсов используй доступные средства браузерного тестирования, в том числе Playwright при необходимости.
- Выбирай минимальный достаточный набор инструментов. Не пропускай необходимые проверки ради экономии токенов.
- Если MCP-сервер недоступен, сообщи об этом и используй подходящий доступный способ; не выдавай его за выполненный вызов.

## Python
- Соблюдай принятый в проекте стиль и организацию модулей.
- Проверяй обработку исключений и корректность асинхронных функций и обработчиков.
- Не допускай блокирующих операций в цикле событий без обоснования.
- Не создавай циклические импорты.

## База данных
- Перед изменением запросов проверяй схему и зависимости от неё.
- Не удаляй и не изменяй данные production без явного согласования.
- При изменении схемы подготавливай необходимые миграции.
- Проверяй транзакции и обработку ошибок операций с данными.

## Тестирование
- Для исправления ошибки по возможности добавляй регрессионный тест.
- После изменения запускай релевантные тесты и проверки; расширяй их охват при необходимости.
- Отделяй выполненные проверки от непроверенных предположений.
- Не утверждай, что тесты пройдены или ошибка устранена, если это не подтверждено результатами.

## Безопасность
- Не раскрывай пароли, токены и API-ключи в ответах, логах и коммитах.
- Не добавляй секреты в репозиторий.
- Не отключай проверки безопасности ради удобства.
- Не изменяй секреты и настройки рабочего окружения без необходимости для задачи.

## Итоговый отчёт
- Кратко объясняй выполненные изменения и перечисляй затронутые файлы.
- Указывай фактически выполненные тесты и их результаты.
- Сообщай об оставшихся проблемах и ограничениях без необоснованных предположений.
