# Онлайн-занятия KRiT

Модуль использует существующие `Person`, `PersonRole`, `PersonMaxIdentity`, расписание и
участников уроков. Отдельной базы пользователей нет. FastAPI выдаёт одноразовый код только
в ранее подтверждённый MAX-аккаунт, хранит хеши кода и серверной сессии и авторизует каждый
HTTP/WebSocket запрос. Доска хранится как упорядоченный журнал идемпотентных операций.

## Компоненты

- `/api/v1/online` — OTP, занятия, комнаты, доска, чат, материалы, задания и опросы;
- `online_lesson_sessions.lesson_id` — постоянная связь комнаты с существующим уроком;
- `online_board_operations` — журнал с уникальными `(room, operation_id)` и `(room, revision)`;
- локальное закрытое хранилище `ONLINE_UPLOAD_ROOT`; файлы выдаются только после проверки урока.

Один процесс FastAPI синхронизирует участников через встроенный room hub. Постоянное состояние
не зависит от памяти процесса. На целевом VPS запускается один процесс API, что исключает расход
памяти на дополнительные координаторы и сохраняет единый порядок живых событий.

## Переменные окружения

Обязательные для production:

```dotenv
ONLINE_PUBLIC_URL=https://school.example/online.html
ONLINE_ALLOWED_ORIGINS=https://school.example
ONLINE_COOKIE_SECURE=true
ONLINE_SESSION_HOURS=12
ONLINE_OTP_PEPPER=<отдельный случайный секрет>
ONLINE_UPLOAD_ROOT=/opt/krit-bot/data/online-assets
ONLINE_UPLOAD_LIMIT_BYTES=15728640
ONLINE_ROOM_STORAGE_LIMIT_BYTES=104857600
ONLINE_TOTAL_STORAGE_LIMIT_BYTES=314572800
ONLINE_MIN_FREE_DISK_BYTES=1073741824
ONLINE_CLEANUP_INTERVAL_SECONDS=900
ONLINE_ABANDONED_ROOM_HOURS=24
```

Существующие `DATABASE_URL`, `MAX_BOT_TOKEN`, `JWT_SECRET` и MAX webhook-параметры сохраняются.
Не помещайте секреты в Git, HTML или JavaScript.

## Обновление сервера

1. Сделайте штатную резервную копию PostgreSQL. Временный каталог онлайн-материалов в неё не добавляйте.
2. Установите новый пакет приложения и зависимости в venv.
3. Заполните новые переменные в `/opt/krit-bot/config/krit-bot.env`.
4. Выполните `/opt/krit-bot/venv/bin/krit-migrate` до запуска приложения.
5. Установите обновлённый `deploy/nginx-krit-api.conf`, затем `nginx -t` и reload.
6. Перезапустите `krit-bot.service`; проверьте `/krit-api/health`, журнал systemd и вход через MAX.

Откат к старому приложению выполняется только вместе с совместимой схемой. Выполните Alembic
downgrade на одну ревизию и верните прошлый пакет; активные материалы заранее экспортируйте через UI.

## Временное хранение и очистка

Каждая комната пишет только в `ONLINE_UPLOAD_ROOT/<room_id>`. Один файл ограничен 15 МБ, комната
100 МБ, весь модуль 300 МБ; дополнительно всегда сохраняется не менее 1 ГБ свободного диска.
Размер известного multipart-файла резервируется до записи, поэтому параллельные загрузки не обходят
квоту. Прерванный или не прошедший сигнатурную проверку файл удаляется сразу.

Кнопка завершения сначала предупреждает о необратимом удалении и предлагает скачать единый PDF.
После подтверждения backend закрывает редактирование и WebSocket, отзывает разрешения, удаляет
каталог комнаты и временные строки доски, снимков, чата, заданий, ответов, опросов и материалов.
Минимальная строка комнаты и событие `room.cleaned` остаются для идемпотентности и технического
аудита. Фоновый цикл повторяет незавершённую очистку после перезапуска и архивирует лишь комнаты,
которые старше настроенного порога и не имеют подключённых участников.

Файлы онлайн-комнат не входят в штатный PostgreSQL backup. Активные временные строки могут попасть
в дамп БД и WAL до очистки; обычное удаление строк не гарантирует немедленного физического удаления
из уже созданных резервных копий. Не запускайте `VACUUM FULL` после каждого урока — используйте
обычный autovacuum PostgreSQL и принятую политику хранения backup/WAL.

## Проверка и наблюдение

```bash
systemctl status krit-bot --no-pager
journalctl -u krit-bot -n 200 --no-pager
curl -fsS https://school.example/krit-api/health
```

Нагрузочный сценарий `bot/tests/load/online_board_ws.py` запускает 10, 20, 30 или 50 WebSocket-
клиентов, отправляет уникальные операции и сверяет итоговую ревизию. Сначала проверяйте 20–30
клиентов на целевом VPS; 50 — отдельный тест с наблюдением за RAM, CPU и задержкой.

```bash
python bot/tests/load/online_board_ws.py \
  --api-base https://school.example/krit-api/api/v1/online \
  --origin https://school.example --room-id 123 \
  --session-token '<временная тестовая сессия преподавателя>' --participants 20
```

Сценарий создаёт реальные операции на странице `load-test`; используйте отдельный тестовый урок.

## Пользовательский сценарий

Преподаватель входит по телефону и коду MAX, выбирает назначенный урок, подготавливает комнату,
запускает её, загружает материал, выдаёт приглашение к доске конкретному ученику, создаёт задания
и завершает урок. Ученик входит тем же способом, видит только свои уроки, по умолчанию наблюдает,
может поднять руку, принять приглашение, сдать назначенную работу и открыть доступные материалы.

## Ограничения текущего выпуска

- DOCX/PPTX хранятся и безопасно скачиваются, но серверное преобразование в PDF не включено.
- Экспорт реализован в PNG для текущей страницы и единый PDF по всем страницам доски.
- Встроенные аудио, видео, запись и демонстрация экрана исключены из продукта по требованиям.
- Текущая живая синхронизация рассчитана на один процесс API, соответствующий ресурсам VPS.
